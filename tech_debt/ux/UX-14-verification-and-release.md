## Объём задачи и критерии приёмки

- Зафиксировать исходный сценарий до реализации: 10 переходов между вкладками,
  уход во время enrichment, открытие списка/переписки после перезапуска,
  медленная сеть, offline/reconnect, вход другим пользователем. Дополнительно:
  смена RU/EN без перезапуска, копирование ID и меню поддержки возле низа экрана.
  Дополнение 10.09: ввод промокода из subscription sheet, переход в детали из
  списка и после создания, scroll/overscroll событий, полная подпись Chat,
  видимость созданных событий при разных локациях и фильтрах.
- Измерять отдельно первый полезный кадр, обновление из сети, число запросов,
  cache hit/miss с причиной, изменение scroll anchor. Диагностика только локальная
  или обезличенная; не логировать имена, сообщения, uid и содержимое snapshots.
- Цель при тёплом кэше: контент на первом кадре построенного route, без ожидания
  сети; нет fallback имени/скелетона/refresh spinner. При одинаковом контенте
  enrichment не меняет scroll offset и расположение остальных карточек.
- Добавлять только сценарные regression tests на эти риски в существующие suites.
  Не закреплять строковыми тестами названия новых helper-методов/расположение кода.
- После Dart-правок — `flutter analyze` и затронутые widget/repository tests.
  После backend-правок — ESLint, tests seed/backfill; при изменении Rules — emulator.
  Перед выпуском — local release gate и review loop по каждому реализованному срезу.
- Финальное сравнение на том же физическом устройстве и режиме сборки выполняется
  с пользователем. Успех unit/widget tests не считать измерением мобильной скорости.

## Результат выполнения

Исходное наблюдение до UX-13 зафиксировано по материалам пользователя: при
профильной локации Phuket и событиях New York discovery-список не объяснял
активный location scope, а переключатель локации был скрыт при валидном профиле.
Production snapshot 10.09.2026: 27 событий, 3 будущих, 24 прошедших, 20 со
старыми неподдерживаемыми локациями, 0 расхождений `events`/`events_public`.

Локальный release gate после всех исправлений прошёл 12.09.2026:

- report: `.git/local-ci/1789202933472-1139e56b-f6af-4f32-923c-9fe4d5ec2a56/result.json`;
- `status: passed`, `exitCode: 0`, `inputsUnchanged: true`;
- fingerprint проверенного состояния: `4a0fbd86ed68354df98f8d0b8af7e19d7c0f147e4443a757c96a3eed1619f35c`;
- `flutter analyze` — без замечаний; полный Flutter suite — 2568 тестов;
- backend ESLint и Node suites, Firestore Rules emulator, legacy fallback
  manifest, performance budget и critical-flow matrix — пройдены.

Перед gate исправлены три устаревших source-contract test: проверка меню поддержки
теперь различает удалённый компонент и актуальный layout delegate, а чатовые тесты
больше не требуют прямого Firestore-чтения после переноса загрузки публичных
профилей в repository. Вместо закрепления приватных имён helper-методов сохранены
поведенческие widget/repository tests и запрет чтения приватного `UsersRecord`.

Review loop: первый проход — 6/10, найдено одно P1 о хрупкой привязке тестов к
внутренним именам; исправлено. Второй свежий проход — 9/10, кодовых замечаний нет;
запрошена только фиксация release evidence, выполнено этим обновлением.

Остальные baseline-сценарии и финальная проверка на физическом устройстве пока не
выполнялись. После этого обновления документа обязателен контрольный release gate;
его report и fingerprint фиксируются в итоговом handoff, чтобы не создавать
самоссылочную правку документа и бесконечную смену fingerprint.

Из UX-11 перенесён обязательный физический замер этапов
`tap → createEvent callable → public preview → confirmed detail`. Числового
baseline до правки нет; сравнение проводится с наблюдаемым исходным сценарием
из приложенных материалов без ретроспективно придуманных значений.
