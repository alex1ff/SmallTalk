## Объём задачи и критерии приёмки

Приоритет: высокий. Это основное исправление повторной загрузки.

- Разделить последний успешный список базовых карточек и дополнительное состояние
  участия/доступа/аватаров. Сохранять базовые карточки сразу после получения, даже
  если пользователь ушёл со страницы до завершения enrichment.
- Ошибка membership или аватара не удаляет базовый список. Различать состояния
  «ещё не проверено», «подтверждено», «ошибка»; отсутствие ответа не равно
  «не участвует». Кэш отображения не является разрешением на действие.
- Разделить freshness и срок хранения: просроченная запись остаётся доступной
  для первого кадра, запускает один фоновый refresh. Первоначальные параметры:
  freshness 5 минут, retention 30 минут, текущий bounded LRU; уточнить по замерам.
- Ключ: uid + локация + фильтры + границы дат/часовой пояс. Не показывать события
  другой локации/фильтра как результат нового запроса. В пределах прежнего ключа
  refresh не очищает список. Истёкшие по времени события фильтровать локально;
  серверные удаления/отмены применять после подтверждения.
- При смене вкладки не сбрасывать фильтры и scroll. Начать с небольшого
  owner-scoped состояния списка вне route; не переносить всё приложение на новую
  архитектуру навигации. Жизненный цикл in-flight запросов должен переживать
  пересоздание страницы и отсекать поздний ответ другого uid/ключа.
- Использовать существующий Firestore cache для восстановления после холодного
  запуска, затем серверную проверку. Пустой/неполный cache query не означает
  отсутствие событий. Не запускать параллельно неограниченные get/listeners;
  владелец запроса и правила отмены должны быть определены.
- Для create/edit/cancel/join/leave применять точечное обновление/инвалидацию.
  Старый background response не перезаписывает результат более нового действия.

Файлы: `event_list_widget.dart`, `event_list_repository.dart`,
`event_list_cache_invalidation.dart`, `ux_session_cache_lifecycle.dart`.

Приёмка: быстрый уход/возврат во время enrichment не запускает видимый cold load;
ошибка участия сохраняет карточку; TTL вызывает тихое обновление; фильтры,
account switch, отмена события и конкурентные join/leave остаются корректными.
Тесты, намеренно ожидающие «whole session uncached» при enrichment failure,
заменить на новый контракт разделённых данных и прав, а не просто удалить.

## Результат выполнения

Причина подтверждена: непустой список попадал в memory cache только после
membership/participants/profile enrichment, а любая частичная ошибка удаляла
всю запись. Поэтому возврат на вкладку снова показывал cold load и повторял
запрос событий.

Сделано:

- базовые карточки сохраняются сразу после base query и не удаляются при ошибке
  участия, списка участников или публичного профиля; cached membership, требующий
  lookup, возвращается в `pending`, поэтому кэш отображения не выдаёт права на
  join/chat;
- freshness 5 минут отделён от retention 30 минут: stale карточки остаются на
  первом кадре, а base query обновляется в фоне; enrichment не продлевает возраст
  базовых данных;
- cache key строго разделяет uid, локацию, часовой пояс, фильтры и локальные
  границы дат; карточки другого ключа больше не показываются как результат;
- истёкшие события фильтруются заново по времени текущего caller. Pending base
  load переиспользуется только если его нижняя граница не уже новой; rollback
  часов запускает более широкий запрос, а поздний узкий ответ не пишет кэш;
- pending membership/participant lookup переиспользуется по event и ключу, но
  завершившаяся ошибка может быть повторена. Mutation epoch и owner token
  отсекают ответы до join/leave/edit/cancel;
- фильтры и scroll сохраняются между пересозданиями вкладки отдельно для uid;
  смена аккаунта синхронизирует owner и не переносит состояние/карточки;
- возврат из event detail инвалидирует только соответствующее событие вместо
  очистки всего event cache. Create по-прежнему безопасно использует глобальную
  invalidation, так как новая карточка могла попасть в несколько ключей.
