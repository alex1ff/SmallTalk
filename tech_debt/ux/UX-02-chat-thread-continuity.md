## Объём задачи и критерии приёмки

Приоритет: высокий. Зависимость: общий кэш из 01.

- Передавать из inbox в `openChatThread` известное представление собеседника,
  проверяя соответствие uid и conversation. Для deep link использовать snapshot
  диалога и общий кэш; live stream обновляет заголовок на месте.
- Сохранить существующие cache-first сообщения, pending-write reconciliation,
  стабильную сортировку `createdAt + documentId`, read markers и обработку
  `permission-denied`. Не заменять сообщения спиннером при reconnect/pagination.
- Проверить сохранение scroll anchor: открытие старой истории, загрузка предыдущих
  сообщений, приход нового сообщения, замена pending на server-confirmed и
  изменение server timestamp. При чтении истории не перемещать пользователя вниз;
  автопрокрутка допустима возле конца переписки или после собственной отправки.
- Добавить/скорректировать `findChildIndexCallback` только там, где изменение
  индексов действительно теряет состояние. Проверить групповые чаты событий
  на тот же контракт без обязательного переписывания их repository.
- Сохранить сообщение и его идентификатор при подтверждении отправки. Ошибки
  отправки остаются видимыми у сообщения, повтор не создаёт дубликат.

Файлы: `open_chat_thread.dart`, `chat_thread_widget.dart`,
`event_group_chat_widget.dart`, `event_group_chat_repository.dart`.
Имеющиеся тесты: `chat_thread_widget_test.dart`,
`chat_thread_cached_messages_contract_test.dart`, тесты группового чата.
Приёмка: заголовок не мигает; уже прочитанный контент остаётся на месте;
нет пропавших/двойных сообщений; при смене пользователя приватный кэш не виден.

## Результат выполнения

- `openChatThread` и deferred-вариант принимают минимальный `ChatPartnerPreview`:
  uid, имя, avatar URL и признак подтверждённого пустого аватара.
- Inbox передаёт preview только после проверки owner/conversation. Экран переписки
  использует его до первого значения live profile stream и проверяет соответствие
  partner uid; данные другого участника не могут попасть в заголовок.
- При появлении live public profile имя и аватар обновляются на месте. Явно пустой
  актуальный avatar не восстанавливает старый snapshot.
- И inbox, и thread пересоздают async-ячейку на границе partner path и валидируют
  public-profile document id до показа. Предыдущий собеседник не может попасть в
  preview нового UID даже при редком изменении участников того же conversation.
- Временная ошибка batch не считается подтверждённым отсутствием: используется
  15-секундный cooldown без таймера и rebuild-loop; явный retry очищает cooldown.
- Cache-first сообщения, scroll anchor, pagination, optimistic reconciliation,
  permission-denied и event group chat не менялись; их существующие контрактные
  и widget-тесты пройдены вместе.
- Проверки: 209 тестов private/event chat и inbox до review-fixes; после fixes —
  85 private-chat/inbox тестов, точечные identity regressions; полный
  `flutter analyze --no-pub`; `git diff --check` — успешно.
- Review loop: два независимых прохода нашли stale-profile reuse в thread и inbox,
  а также неверное объединение missing/failed; все замечания устранены. Третий
  проход не запускался по лимиту 1–2 прохода.
- Commit и device QA пока не выполнялись.
