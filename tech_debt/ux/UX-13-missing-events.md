## Объём задачи и критерии приёмки

Приоритет: высокий; диагностику начать первой среди новых задач. Комментарий
заказчика приведён текстом (отдельного восьмого изображения нет). Локация —
гипотеза, а не установленная причина. Не расширять видимость всех событий вслепую.

- Найти конкретный аккаунт заказчика и 2–3 созданных события по подтверждённому
  идентификатору/ссылке/названию и времени; не угадывать аккаунт по отображаемому
  имени. Если данных нет, запросить их на этапе диагностики. Начать с read-only.
- Для каждой записи сопоставить `events` и `events_public`: существование,
  organizerId, status, startsAt, timezone, countryCode, cityKey, levelMin/levelMax.
  Проверить ответ создания и наличие записи, а не только факт нажатия кнопки.
- Сопоставить с эффективными фильтрами пользователя: локация профиля/выбранная
  локация экрана, день/неделя/месяц, уровень. Проверить старые значения стран и
  cityKey после перехода к четырём локациям; не путать язык UI с фильтром события.
- Проверить, не стали ли события прошедшими: общий запрос содержит
  `startsAt >= now`. Проверить преобразование выбранного местного времени в UTC
  и границы дат по timezone локации, особенно при другом часовом поясе устройства.
- Различить discovery-список и «Мои события»: первый фильтруется по месту/времени,
  второй должен давать организатору понятный доступ к созданным событиям и истории
  согласно существующему контракту. Проверить cancellation, лимиты и пагинацию.
- Проверить ошибки Rules/index/callable и ситуацию, когда ошибка показывается как
  пустой список. Если projection отсутствует/устарела, установить причину и только
  затем подготовить адресный repair; не запускать массовый backfill по гипотезе.
- Проверить кэш после создания и переключения локации. Для скрытого фильтрами
  результата показать активную локацию и понятное объяснение пустого списка,
  действия «Сбросить фильтры»/«Мои события». Не менять профиль молча.

Файлы: `event_list_repository.dart`, `event_list_date_bounds.dart`,
`event_city_catalog.dart`, `event_history_repository.dart`, экран «Мои события»,
`create_event.js`, `event_public_projection.js`, `sync_event_public_projection.js`.

Приёмка: для проверенных событий есть точное объяснение включения/исключения
из выдачи. Если найден баг — regression test на подтверждённую ветку; если
фильтрация корректна — доступный путь к своим событиям и понятный контекст фильтра.
Сопоставить результат с аккаунтом заказчика после исправления, не только fixtures.
