## Объём задачи и критерии приёмки

Приоритет: высокий. Выполнять после 03, чтобы удаление skeleton не дало пустой экран
на каждом возврате.

- Убрать `_EventListLoadingState` с карточкой-скелетоном. На повторном открытии
  отрисовать сохранённые карточки; фоновое обновление визуально не показывать.
- При самом первом открытии без любых данных оставить заголовок/фильтры и чистую
  область списка. При длительном ожидании допустим спокойный текст загрузки
  в заранее выделенном месте; стартовый ориентир задержки — 400 мс, не стандарт
  платформы. Ошибка должна заканчиваться доступным retry, а не вечной пустотой.
  Не задерживать появление готовых карточек искусственным minimum loading time.
- Убрать «Проверяем участие». Если статус известен — сохранить подтверждённый вид
  CTA при refresh. Если неизвестен — нейтральное действие «Подробнее», открывающее
  доступное превью. На уже открытой карточке разрешать окончательный CTA после
  подтверждения, сохраняя его геометрию. Не выдавать неизвестное участие за Join.
- Проверку права на Join/Leave/Chat выполнять перед соответствующим действием;
  после нажатия допустим локальный busy-state. Не разблокировать полный event chat
  или платный контент на основании устаревшего кэша. Текущие серверные проверки
  подписки, вместимости и участия сохраняются.
- У аватаров, метаданных и кнопок сохранять занимаемое место. Не фиксировать
  высоту всей карточки ценой обрезки длинного названия/крупного системного шрифта.
  Обновление аватара или metadata не должно менять соседние отступы.
- На уровне event repository корректно определять конец по числу сырых документов
  страницы, а не по количеству карточек после фильтрации/десериализации. Если нужна
  явная `hasMore`, расширить контракт локально; не менять глобальный pagination
  helper без проверки остальных потребителей.
- Для неполной серверной страницы сразу завершать пагинацию. Для полной —
  догрузка курсором; пустая cache page не должна завершать серверную пагинацию.
  Автоматическая фоновая проверка не рисует спиннер/«Больше событий нет» под одной
  карточкой. Нижний индикатор уместен только при реальном ожидании следующей
  порции пользователем и не двигает уже видимые карточки.

Приёмка: карточка появляется один раз и догружается на месте; 1 событие при размере
страницы 20 не вызывает лишний серверный запрос за пустой следующей страницей;
ровно 20/больше 20, фильтры уровня и timezone не теряют события; Join/Chat безопасны
при unknown/stale статусе. Проверить координаты карточек до/после enrichment.

## Результат выполнения

Причина подтверждена: экран отдельно показывал skeleton, визуальный refresh и
состояния проверки участия, а окончание пагинации определялось по наличию cursor,
из-за чего неполная первая страница запускала лишнюю фоновую загрузку.

Выполнено:

- первая загрузка оставляет стабильную область списка, сохранённые карточки
  обновляются без визуального индикатора;
- неизвестное участие показывает безопасное действие «Подробнее», открывающее
  публичные детали; Join/Chat не разблокируются до подтверждения;
- repository возвращает локальный `hasMore`, рассчитанный по числу сырых Firestore
  документов, и сохраняет его при фильтрации уровня;
- неполная страница сразу завершает пагинацию; автоматическая догрузка не рисует
  spinner или «Больше событий нет», ошибка сохраняет доступный retry.
