## Объём задачи и критерии приёмки

Приоритет: высокий. Фото 2 и 6: полноэкранное «Loading event…».
Связано с 03–04, но это отдельный экран и отдельный источник данных.

Подтверждено: `EventDetailRouteWidget` использует `EventDetailRepository`, имеет
собственный кэш и показывает loading scaffold, пока результат не разрешён.
Repository использует callable `getEventDetails`. Точное время запроса не измерено.

- Из списка передавать имеющиеся публичные поля как начальное превью деталей:
  название, описание-превью, организатор, дата, уровень, локация. Различать
  публичное превью и полный подтверждённый detail record в типах/состоянии.
- При наличии разрешённого кэша деталей показывать его сразу и обновлять в фоне.
  Не ждать аватары/участников для отрисовки уже известной основной информации.
- Для deep link без кэша оставить работающие заголовок и Back; после получения
  данных раскрыть экран без последовательности нескольких полноэкранных лоадеров.
- Перед показом приватных полей и включением защищённых действий подтвердить
  актуальный доступ. Превью не должно открывать место встречи или чат, если они
  недоступны этому пользователю по текущим правилам.
- Измерить этапы: переход → callable → основная модель → участники/профили.
  Убрать повторные одинаковые запросы; независимые запросы распараллелить только
  там, где это не нарушает проверку доступа. Не покупать minInstances/новые ресурсы
  ради предполагаемого cold start без измерений и отдельного решения.

Файлы: `event_detail_route_widget.dart`, `event_detail_repository.dart`, переходы
из `event_list_widget.dart`, `nav.dart`, `get_event_details.js` в backend.
Приёмка: при входе из известной карточки видна её информация сразу; ошибка
догрузки не стирает превью; удаление/отзыв доступа корректно обновляют экран.

## Результат выполнения

Причина подтверждена: переход из списка передавал только `eventId`, поэтому route
не мог использовать уже показанные публичные данные и всегда ждал первый ответ
`getEventDetails` либо session cache.

Выполнено:

- список передаёт типизированное публичное превью через in-memory navigation
  extra; deep link по-прежнему работает только по `eventId`;
- preview сразу показывает название, публичное описание, организатора, дату,
  язык, уровень и публичную вместимость;
- точное место, участники, Join/Leave/Chat и organizer controls не берутся из
  preview и остаются закрыты до подтверждённой detail-модели;
- ошибка догрузки не стирает preview, а подтверждённый missing/full detail
  корректно заменяет его;
- cold deep link сохраняет заголовок и Back во время ожидания.
