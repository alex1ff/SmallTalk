# P2-02 — единая политика навигации и типизированные аргументы

**Приоритет:** P2 · **Размер:** M/L · **Зависимости:** P0-01, P2-03
**Цель:** убрать скрытые падения и трудноотслеживаемые переходы, не меняя
публичные route paths и deep links.

## Почему это долг

Маршруты объявлены централизованно в `lib/flutter_flow/nav/nav.dart`, но
переходы и возвраты в feature-коде используют смесь GoRouter и
`Navigator.pop`. В аргументы маршрутов передаются карты, query-параметры и
`DocumentReference`, которые затем приводятся через `as`/`dynamic`. Это
затрудняет поиск вызовов, обработку back gesture и восстановление после
авторизационного redirect. Объём — около 32 `Navigator.pop` и множество
разрозненных `context.go`.

## Минимальный план

1. Составить таблицу route path → экран → обязательные/необязательные
   параметры → источник перехода; зафиксировать текущие deep links.
2. Ввести небольшие immutable DTO аргументов для реально используемых
   межэкранных переходов (не для каждого виджета): например `CallInfoArgs`,
   `EventDetailsArgs`. Парсинг query делать в одном месте с понятной ошибкой.
3. Оставить GoRouter единственным способом перехода между страницами;
   `Navigator.pop` сохранить только для закрытия локального dialog/bottom
   sheet. Сначала мигрировать только cross-page вызовы, не переписывая модалки.
4. Убедиться, что auth redirect, pending redirect, back и повторное открытие
   приложения используют один и тот же источник состояния.

## TDD/проверки

- Тесты таблицы маршрутов: авторизованный/неавторизованный вход, неизвестный
  path, отсутствующий и malformed параметр, возврат назад.
- Тесты DTO: корректная сериализация, URL encoding, `null` и старый формат
  параметра на время миграции.
- Интеграционный smoke для login → home → call/event → back.

## Подводные камни

- Нельзя менять имена callable/Firestore ID или route paths без redirect и
  обратной совместимости.
- `DocumentReference`, `Timestamp` и Unicode в query нельзя передавать через
  неявный `toString`; нужен явный безопасный формат.
- Асинхронный auth redirect может сработать до загрузки профиля; не добавлять
  второй redirect в каждом экране.
- Проверить iOS swipe-back, Android system back и web/browser history.

## Не делать

Не переписывать весь FlutterFlow router, не вводить новый routing framework и
не превращать локальные sheets в полноценные routes только ради унификации.

## Готово, когда

- cross-page переходы имеют один понятный API и typed args;
- текущие paths/deep links работают;
- ошибки параметров не приводят к `CastError`/белому экрану;
- добавлены тесты redirect, back и malformed input;
- `flutter analyze` и профильные тесты зелёные.

## Риск, abort и откат

- **Abort:** broken deep link, back gesture, auth redirect loop или CastError в
  production smoke; миграцию остановить на последнем route group.
- **Откат:** вернуть предыдущий route registration/DTO adapter commit, сохранив
  обратный parser для уже опубликованных links.
- **Необратимость:** отсутствует, пока paths и persisted arguments не меняются.
